# Contributing

Спасибо за интерес к проекту **RecipeTelegramBot**!

Проект является учебным и портфолио-проектом, поэтому предложения по улучшению, исправления и небольшие изменения приветствуются.

## Как предложить изменение

1. Создайте fork репозитория.
2. Создайте отдельную ветку для изменения:

```bash
git checkout -b feature/my-change
```

3. Внесите изменения.
4. Убедитесь, что проект собирается без ошибок:

```bash
dotnet build
```

5. Если изменение содержит новую логику, по возможности добавьте или обновите тесты.
6. Создайте commit с понятным описанием изменения:

```bash
git commit -m "Add recipe validation"
```

7. Отправьте ветку в свой fork:

```bash
git push origin feature/my-change
```

8. Создайте Merge Request.

## Требования к изменениям

При внесении изменений желательно:

* сохранять существующую архитектуру проекта;
* не смешивать несколько независимых изменений в одном Merge Request;
* не добавлять секреты, токены и пароли в репозиторий;
* не коммитить файлы `.env` и другие файлы с конфиденциальными данными;
* придерживаться существующего стиля кода;
* использовать понятные имена классов, методов и переменных;
* по возможности добавлять тесты для новой бизнес-логики.

## Архитектура

Проект разделён на следующие основные части:

* `RecipeBot.Domain` — доменные модели, enum и интерфейсы репозиториев;
* `RecipeBot.Application` — бизнес-логика и обработчики;
* `RecipeBot.Infrastructure` — работа с базой данных и реализации репозиториев;
* `RecipeBot.Telegram` — интеграция с Telegram Bot API и запуск приложения.

При добавлении новой функциональности следует по возможности сохранять это разделение ответственности.

## Commit messages

Для commit рекомендуется использовать короткое описание изменения на английском языке.

Примеры:

```text
Add recipe validation
Fix stage image handling
Refactor recipe handler
Update database migration
Add Docker configuration
```

## Merge Requests

В описании Merge Request желательно указать:

* что было изменено;
* зачем было внесено изменение;
* какие части проекта затронуты;
* как изменение было проверено.

Например:

```text
### Changes

- Added recipe name validation.
- Updated AddNewRecipeHandler.
- Added validation tests.

### Verification

- dotnet build
- dotnet test
```

## Issues

Для предложений и сообщений об ошибках желательно указать:

* краткое описание проблемы;
* шаги для воспроизведения;
* ожидаемое поведение;
* фактическое поведение;
* при необходимости — фрагмент лога или скриншот.
