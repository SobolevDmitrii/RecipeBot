# История изменений

## [1.2.0] — 2026-09-22

### Добавлено

* Фоновый `SessionRecoveryService`: проверка незавершённой обработки сессий каждые пять минут и уведомление пользователя с предложением выполнить `/start` или `/cancel`.
* Учёт обрабатываемых сессий в Redis Sorted Set `processing:sessions`; сохранение `ChatId` и `CurrentUpdateId` в пользовательской сессии.
* Проект `RecipeBot.UnitTests` на NUnit с Moq и AutoFixture: тесты создания и просмотра рецептов, стартового меню, Telegram-сервиса и обнаружения зависших сессий.
* Проект `RecipeBot.IntegrationTests` на NUnit и Testcontainers: тесты репозиториев PostgreSQL и сценариев создания и просмотра рецептов с PostgreSQL и Redis.я

### Изменено

* `UserSessionsStore` перенесён из Application в Infrastructure и зарегистрирован через `IUserSessionStore`.
* В запросы создания и просмотра рецептов передаётся идентификатор Telegram-обновления для отслеживания обработки.
* После успешной обработки Telegram-сервис очищает `CurrentUpdateId` и удаляет сессию из списка обрабатываемых.
* Актуализирован README: фоновые службы, структура решения, тестирование и запуск инфраструктуры через Docker Compose.

### Исправлено

* При переходе в стартовое меню явно устанавливается состояние `UserStates.Start`.

## [1.1.1] — 2026-09-09

### Изменено

* Сессии пользователей переведены на хранение в Redis.
* Данные сессии отделены от Domain-сущностей с помощью DTO.
* Упрощён `UserSessionsStore`: удалено устаревшее in-memory хранение сессий.
* Удалён отладочный вывод состояния пользовательских сессий через `Console.WriteLine`.
* Уточнена передача данных пользователя в `GetOrCreateUserRequest`: вместо Telegram `Update` передаются только необходимые данные (`ChatId`, `FirstName`).
* Ограничен набор обрабатываемых Telegram-обновлений: `Message` и `CallbackQuery`.
* Добавлено подтверждение `CallbackQuery` через `AnswerCallbackQuery`.

### Исправлено

* Убраны preview-версии `Microsoft.Extensions.*` 11.x.
* Зависимости `Microsoft.Extensions.*` приведены к стабильной версии 10.x, соответствующей .NET 10.
* Удалена лишняя зависимость `Microsoft.EntityFrameworkCore.Sqlite`.

### Архитектура

* Убрана зависимость Application-логики от полного Telegram `Update` в `GetOrCreateUserRequest`.
* Redis используется как единое хранилище пользовательских сессий.
* Для сериализации состояния сессии используются DTO без циклических ссылок на Domain-сущности.
* Упрощён интерфейс работы с пользовательскими сессиями.

## [1.1.0] — 2026-09-05

### Добавлено

* Раздел «Мои рецепты».
* Просмотр списка сохранённых рецептов.
* Поиск рецептов по полному и частичному названию.
* Фильтрация рецептов по категории.
* Пагинация списка рецептов.
* Просмотр выбранного рецепта.
* Просмотр этапов приготовления.
* Пагинация этапов приготовления.
* Удаление рецепта.
* Отображение фотографии рецепта при просмотре.
* Отображение фотографии этапа приготовления.

### Изменено

* Расширен `HandlerResult` для поддержки изображения.
* Добавлено хранение текущего просматриваемого рецепта в `UserSession`.
* Добавлено хранение списка рецептов в пользовательской сессии для работы пагинации.
* Обновлена маршрутизация callback-запросов для работы со списком и выбранным рецептом.
* Добавлены callback-данные для навигации между страницами рецептов и этапами.

### Архитектура

* Добавлен `GetUserRecipesHandler`.
* Добавлена отдельная пагинация списка рецептов.
* Добавлена отдельная пагинация этапов рецепта.
* Расширен state-based сценарий работы пользователя с рецептами.
* Логика работы со списком рецептов вынесена в Application layer.

## [1.0.0] — 2026-09-04

### Добавлено

* Создание рецептов через Telegram-бота.
* Выбор категории рецепта.
* Добавление ингредиентов.
* Добавление фотографии рецепта.
* Добавление этапов приготовления.
* Добавление фотографии к этапу приготовления.
* Сохранение рецептов в PostgreSQL.
* Управление состоянием пользовательского сценария.
* Docker-конфигурация для запуска приложения.

### Архитектура

* Разделение проекта на Domain, Application, Infrastructure и Telegram.
* Использование MediatR.
* Использование Entity Framework Core.
* Использование Repository pattern.
* Использование `IDbContextFactory`.
