# Первое развёртывание на Synology DS224+

Комплект готовится для `linux/amd64`: образ бота, PostgreSQL 18 и Redis 8,
резервная копия PostgreSQL, Compose и отдельный `.env` для NAS.
Redis с компьютера не переносится: незавершённые диалоги и черновики начнутся заново.
База на компьютере остаётся сохранённой. Локальный бот останавливается перед
финальным дампом и должен оставаться остановленным, пока работает бот на NAS.

## Установка

1. В File Station создайте папку `docker/recipebot` на томе 1.
2. Загрузите архив комплекта и распакуйте его в эту папку. В ней непосредственно
   должны находиться `install.sh`, `compose.yml`, `.env`, `images.tar`,
   `database.dump` и `SHA256SUMS` (без дополнительной вложенной папки).
3. В SSH на NAS выполните:

   ```sh
   cd /volume1/docker/recipebot
   sudo sh install.sh
   ```

Скрипт проверит контрольные суммы, загрузит образы без скачивания из интернета,
создаст контейнеры PostgreSQL и Redis, проверит пустоту новой базы и Redis,
восстановит PostgreSQL одной транзакцией, применит миграции и запустит бота.
Существующая непустая база без маркера восстановления не перезаписывается.
Повторный запуск после успешного восстановления не импортирует дамп заново.
Объекты Compose имеют имя проекта `recipebot-synology`.

## Проверка

```sh
sudo docker compose -p recipebot-synology ps -a
sudo docker compose -p recipebot-synology logs --tail 60 bot
sudo docker compose -p recipebot-synology exec -T postgres psql -U myuser -d myrecipedb < counts.sql
```

Сравните количество записей с `source-counts.txt`. Отправьте боту `/start`,
откройте «Мои рецепты» и проверьте сохранённый рецепт.
Если на NAS доступна только команда `docker-compose`, используйте её вместо
`docker compose` в командах проверки. В установщике выбор выполняется автоматически.

Тома PostgreSQL, Redis и логов постоянные; порты БД и Redis наружу не публикуются.
Не запускайте `down -v`: это удалит данные томов.
Архив и `.env` содержат секреты, а дамп — пользовательские данные. Храните их
в папке с доступом только для администратора. После успешного переноса настройте
регулярный `pg_dump` и хранение резервных копий отдельно от рабочего тома.

## Возврат на компьютер до начала работы пользователей

Остановите бот на NAS:

```sh
sudo docker compose -p recipebot-synology stop bot
```

Затем на компьютере: `docker start recipebot-bot-1`.
Если на NAS уже появились новые рецепты или изменения, сначала перенесите
актуальную базу обратно; локальная копия содержит только данные на момент дампа.
